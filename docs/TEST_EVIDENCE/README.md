## Funded integration repair — 5 September 2026

The owner subsequently reported $10 in API credits and authorized careful tests.
These results supersede the earlier unfunded attempt, without claiming an

### Reproduced causes and fixes

- The exact GPT-5.4 request returned HTTP 400: function tools with a non-`none`
  reasoning effort require Responses. OpenAI now uses `/v1/responses` with low
  reasoning, streaming, explicit `store:false`, full reasoning/tool-item replay,
  and normalized usage accounting. Custom compatible endpoints and Groq retain
  Chat Completions. Partial or failed rounds never execute tools.
- Realtime rejected a typed turn's 37-character `item.id`; its limit is 32.
  IDs are now 29 characters. Idle turns no longer cancel nonexistent output.
  Failed/incomplete responses are surfaced and the owned call is hung up.
- Local allowances, provider billing/quota, invalid requests, authentication,
  rate limits and incomplete replies no longer share the misleading generic
  availability notice. Only fixed safe error categories reach UI/logs.
- A silent chained recording previously uploaded even without speech; local
  voiced-duration gating now blocks that upload. Full transcription-hint echoes
  are discarded on the server. No user's existing messages were removed.
- The live smoke now requires the configured primary model/provider and a
  nonempty reply. Groq fallback is recovery evidence, never a primary pass.
  Provider-free tests do not borrow the paid host's saved smoke result.
- Final production reload exposed a separate routing issue: `.env.local`'s
  development API address was compiled into the production UI. Production now
  always uses its own origin; the development-only URL remains available in dev.
  A regression test covers an old localhost:8787 setting in a production build.
